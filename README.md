# LAIM traces dataset converter

Нода восстанавливает наблюдения об ответах пользователю по **одному подтверждённому протоколу**. Похожий текст внутреннего span не является доказательством доставки ответа.

## Входы

`monitoring_traces` — таблица spans; `monitoring_metric` — подтверждённый v3; `traces_validation_result` — результат проверки телеметрии; `selection` — идентичность источника и версии. Неподтверждённое определение или провал DQ дают пустую UMR и `not_ready` до извлечения.

`solution_version` обязательна в исходных spans выбранного агента и должна совпадать с подтверждённым определением. Отсутствующая, смешанная или старая версия даёт `source_version_unverified` и пустую UMR. Версия из `selection` не подставляется вместо наблюдаемой. Источник должен передавать реальную версию при сборе; окно и полнота выгрузки требуют отдельной проверки источника.

## Профили извлечения

| Профиль из evaluation | Доказательство ответа | Неоднозначность |
|---|---|---|
| `fipa_external_reply_v1` | FIPA correlation key и явно заданный `external_party` | Конфликтующие пары и незавершённые ключи не публикуются |
| `aef_boundary_v1` | Пара request/response на `input_request`, который при подключении подтверждён как внешняя граница | Внутренний `start_agent` не заменяет границу |
| `state_single_request_v1` | Подтверждено: один логический запрос на trace; вопрос и ответ в финальном state | Различающиеся exit в одном trace не разрешаются выбором последнего |

Профиль выбирается при подключении, а не по большинству соседних трейсов. Нет fallback на родительский span, произвольный `full_answer` или другой профиль.

## Выходы и готовность

`monitoring_umr` — плоская таблица turns для всех режимов оценки, в том числе dialogue. `reference_group_id` и `turn_index` сохраняют группировку; источники вопроса/ответа, trace/span ID, время, `definition_id` и `dataset_role=monitoring` сохраняются для проверки происхождения. Ассесор собирает единицы dialogue без потери покомпонентных свидетельств.

`output_answer` — текст ответа. `prediction_observable` явно выбирает `route_label` либо `output_answer`; формула accuracy сама по себе не означает маршрутизацию. Target на мониторинге не придумывается.

`evaluation_ready` запрещает оценку при неполном извлечении или недоступных обязательных свидетельствах. Текущие профили доказывают QA/маршрут; полный history, факты клиента, знания и результаты инструментов пока не извлекаются как проверенные свидетельства. Их требование даёт отказ, а не оценку по урезанному контексту. Поддержку этих классов нужно завершить перед общим production-допуском.

`processing_report` содержит DQ, счётчики извлечения, потерь и причины; `parquet_test_dataset` сохраняет полный текст. Excel — вспомогательный экспорт с контролем ограничения длины ячеек и строк, начинающихся с `=`.

```bash
python3 -m pytest -q
ruff check .
```

Порты указаны в descriptor. Разворачивать с согласованными потребителями v3; физический формат UMR остаётся v2 с дополнительными provenance-полями, проекция конвертера имеет версию v3.

Объявленная evaluation.prediction_observable требуется независимо от scoring.method. Для итоговой человеческой оценки route_label публикуется как scenario, output_answer — как ответ; metadata содержит prediction_mapping. Отсутствующая величина даёт ready_for_scoring=false. Для accuracy сохраняется отдельная prediction-колонка, target остаётся только в reference.
